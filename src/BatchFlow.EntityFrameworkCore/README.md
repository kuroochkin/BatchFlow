# BatchFlow.EntityFrameworkCore

Независимый от провайдера адаптер EF Core для BatchFlow. Проект использует `Microsoft.EntityFrameworkCore` 9.0.15 и общую платформу репозитория `net9.0`. Конкретный EF-провайдер и строку подключения настраивает приложение.

## Что уже работает

- `EfCoreBatchSource<TContext, TItem, TCheckpoint>` читает по LINQ/keyset и освобождает отдельный контекст на каждую порцию до выдачи пакета.
- `EfCoreBatchSourceOptions` требует фабрику запроса, стабильную сортировку, SQL-предикат продолжения, извлечение checkpoint и его сравниватель; допускает убывающий и составной порядок.
- `EntityFrameworkCoreContextOptions<TContext>` принимает `IDbContextFactory<TContext>`, синхронную или асинхронную фабрику. Готовый внешний `DbContext` поддерживает только базовый класс собственных источников.
- `EntityFrameworkCoreBatchSourceBase<TContext, TItem, TCheckpoint>` управляет контекстом в пределах перечисления и проверяет пакеты наследника.
- `FromEntityFrameworkCore(options)` создает готовый источник; `FromEntityFrameworkCore(source)` и обычный `From(source)` подключают существующий.
- `FromDbContext` поддерживает source, options, `IDbContextFactory`, контролируемую фабрику и configure-delegate; `CreateBatchSource` на фабрике позволяет создать source отдельно.
- Retry, параллелизм, события и checkpoint coordination остаются в стандартном runtime.

EF-хранилища checkpoint нет: используется стандартный `WithCheckpoint`. Готовый источник не допускает offset-пагинацию основной цепочки, проверяет строгое продвижение позиции и читает одну дополнительную строку для проверки границы пакета. Уникальность ключей и согласованность изменяющейся таблицы требуют отдельного решения приложения.

## Владение контекстом

Фабрика передает каждый полученный контекст источнику. `EfCoreBatchSource` освобождает его на каждую порцию до передачи данных обработчикам; базовый класс - при завершении перечисления, ошибке, отмене или раннем освобождении перечислителя. Сама фабрика не освобождается. Для фабрики с пулом вызов `DisposeAsync` возвращает контекст в пул.

Ошибки освобождения ресурсов не подменяют первичную ошибку чтения или отмену. Если чтение прошло успешно, первая ошибка освобождения передается вызывающему коду. Освобождение обоих ресурсов вызывается даже при ошибке одного из них.

Готовый контекст всегда остается во владении приложения. Одновременные перечисления одного source отклоняются; использование того же контекста через другие source, handlers или код приложения запрещено контрактом, но не контролируется глобальной блокировкой. Передавать готовый контекст с владением адаптера нельзя: это привело бы к использованию уже освобожденного экземпляра при следующем запуске.

Использование и ограничения: [готовый keyset-source](../../docs/11-ef-core-source.md). Полный исполняемый пример: [SQLite в памяти](../../samples/BatchFlow.EntityFrameworkCore.Sample/Program.cs). Собственные наследники и внешние контексты: [общие точки расширения](../../docs/10-entity-framework-core.md).

Регистрации `IServiceCollection` находятся в необязательном `BatchFlow.EntityFrameworkCore.DependencyInjection`, а не в базовом адаптере. Пакет использует фабрику приложения, не выбирает провайдер и не создает контекст при регистрации. [DI, FromDbContext и владение](../../docs/12-dependency-injection.md).
