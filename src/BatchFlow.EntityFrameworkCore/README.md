# BatchFlow.EntityFrameworkCore

Независимый от провайдера каркас адаптера EF Core для BatchFlow. Проект использует `Microsoft.EntityFrameworkCore` 9.0.15 и общую платформу репозитория `net9.0`. Конкретный EF-провайдер и строку подключения настраивает приложение.

## Что уже работает

- `EntityFrameworkCoreContextOptions<TContext>` принимает `IDbContextFactory<TContext>`, синхронную или асинхронную фабрику, готовый внешний `DbContext`.
- `EntityFrameworkCoreBatchSourceBase<TContext, TItem, TCheckpoint>` управляет контекстом в пределах перечисления и проверяет пакеты наследника.
- `FromEntityFrameworkCore(source)` подключает источник к существующему builder; обычный `From(source)` также работает.
- Retry, параллелизм, события и checkpoint coordination остаются в стандартном runtime.

Готового универсального LINQ/keyset-источника и EF-хранилища checkpoint пока нет. Базовый класс не реализует запросы и не обещает восстановление без соответствующей реализации наследника.

## Владение контекстом

Фабрика передает каждый созданный контекст источнику. Он освобождается после полного чтения, ошибки, отмены или раннего освобождения перечислителя. Сама фабрика не освобождается. Для фабрики с пулом вызов `DisposeAsync` возвращает контекст в пул согласно поведению EF Core.

Ошибки освобождения ресурсов не подменяют первичную ошибку чтения или отмену. Если чтение прошло успешно, первая ошибка освобождения передается вызывающему коду. Освобождение обоих ресурсов вызывается даже при ошибке одного из них.

Готовый контекст всегда остается во владении приложения. Одновременные перечисления одного source отклоняются; использование того же контекста через другие source, handlers или код приложения запрещено контрактом, но не контролируется глобальной блокировкой. Передавать готовый контекст с владением адаптера нельзя: это привело бы к использованию уже освобожденного экземпляра при следующем запуске.
